# 보아요 UI와 기본 앱 예제

v14에서 도입한 공통 UI와 텍스트 에디터·설정·대시보드를 설명한다. 현재 적용본 **v16c**에 이 기능과 추가 데스크톱 앱·키 탐색이 포함돼 있다. 2026-11-27 설정·대시보드 화면과 키 탐색을 실보드에서 확인했다. 에디터 편집·저장 등 PC·QEMU 검사와 실보드 관측 범위는 [README](README.md)와 [키 입력 문서](KEYBOARD.ko.md)에 구분했다. 아래 `ui-examples-*` 이미지·검증 파일은 v14 도입 당시의 기록이다.

## 공통 화면 동작

앱을 열면 S색으로 채운 창을 먼저 게시한다. 앱은 별도 화면 버퍼에 첫 화면을 완성하고, B색 배경과 콘텐츠를 함께 게시한다. 화면 일부만 준비된 상태를 차례로 노출하지 않는다. 이후에는 앞서 보낸 화면과 비교해 실제 바뀐 영역만 전송한다. 바뀐 픽셀이 없으면 화면을 게시하지 않는다.

앱이 만든 최신 화면을 기준으로 변경 영역을 합친다. 입력 이벤트는 순서를 보존하지만, 모든 중간 화면을 반드시 그리지는 않는다. S/B 색을 바꾸는 경우에도 새 콘텐츠와 같은 `commit_surface`에 담아 한 번에 반영한다.

이동은 기존처럼 S색 삼각형 타일 하나를 움직인다. 크기 조절은 콘텐츠를 숨기고 S색으로 채운 빈 창을 늘리고 줄인다. 실제 창과 콘텐츠는 놓을 때 한 번 갱신한다. 삼각형 타일의 배치에 따라 외곽 모양은 달라진다.

## 창 조작 아이콘

위쪽 닫기, 아래쪽 이동, 오른쪽 아래 크기 조절 배치를 유지했다. 둥근 창 모서리나 창 테두리는 추가하지 않았다.

| 항목 | 크기·표시 |
|---|---|
| 아이콘 | 기준 폭 28픽셀, 굵은 흰색 선 |
| 아이콘 받침 | 36픽셀 검정 사각형 |
| 클릭 범위 | 48픽셀 |
| 마우스를 올렸을 때 | 흰색 테두리 |
| 누른 상태 | 강조색(RGB332 228번) |

아이콘이 중심 타일 밖으로 나가면 인접 타일까지 그린다. 앱 콘텐츠를 덮지 않도록 표시할 셀을 검사한다. 고정소수점 투영을 거친 검사에서 닫기·이동·크기 조절의 흰색 영역은 각각 23×23, 26×28, 26×26픽셀이었다. 이는 PC에서 계산한 결과이며, 실제 HDMI 화면의 가독성은 보드에서 확인해야 한다.

## 세 가지 앱

| 앱 | 구현한 기능 | 범위와 제한 |
|---|---|---|
| 텍스트 에디터 | 입력·삭제, 방향키, Home/End, 줄바꿈, 클릭으로 커서 이동, 저장 버튼과 Ctrl+S | ASCII 문서 최대 16 KiB. 실행 취소·선택·파일 선택창은 아직 없음 |
| 설정 | 자기 창의 S/B 색 선택과 적용, 포인터 닷 켜기·끄기 | S/B는 해당 창에만 적용. 포인터 표시는 WM 전체에 적용. 재실행 시 설정을 복원하지 않음 |
| 대시보드 | 가동 시간, 메모리 사용량, CPU 사용률, 수동 새로고침 | 실제 `/proc` 값. 2초마다 표본 수집. CPU는 첫 유효한 차분을 얻기 전까지 수집 중으로 표시 |

네이티브 앱은 실행 파일에 포함된 ASCII 글꼴을 사용한다. **한글 글꼴과 한글 입력기는 아직 없다.** 브라우저 조작 모형에서 한글이 입력되더라도 보드 앱의 한글 지원을 뜻하지 않는다. 기본 콘텐츠 버퍼는 RGB332 360×240이며, 창 크기를 바꾸면 이 콘텐츠를 다시 투영한다. 자동으로 글자 수나 문단 배치를 바꾸는 기능은 아직 없다.

편집기는 기본적으로 `/tmp/boayo-note.txt`를 사용한다. `/tmp` 파일은 재부팅하면 사라질 수 있다. 유지할 문서는 `--file`로 저장 가능한 영구 경로를 지정한다. 저장할 때는 같은 디렉터리에 임시 파일을 쓰고 동기화한 뒤 이름을 바꾼다. 저장에 실패하면 원래 파일을 유지하고 실패 상태를 표시한다.

## 앱 입력과 화면 갱신

`src/app_ui.hpp`가 화면 버퍼·그리기·부분 갱신을 맡는다. `src/example_apps.hpp`에 앱 동작을 모았고, `src/example_apps.cpp`가 실행 진입점이다.

- 앱은 자기 소켓에서 `wait_events`를 호출한다. 대기 시간은 1–1000 ms다. `app_events`와 `poll_events`로 즉시 읽을 수도 있다.
- 앱별 이벤트 큐는 최대 128개다. 다른 앱이나 제어 연결은 해당 큐를 읽을 수 없다. 넘치면 오류를 반환하며 키 입력을 조용히 버리지 않는다.
- 콘텐츠 클릭 좌표는 투영된 창에서 원본 콘텐츠 좌표로 변환한다. 창 조작 버튼을 누른 동작은 앱 클릭으로 전달하지 않는다.
- `input_text`와 `input_key`는 선택한 앱에 전달한다. 문자·누름·놓기의 순서는 보존한다. WM의 연속 좌표 입력만 최신 값으로 합친다.
- 화면 게시 완료와 앱 입력 접수는 별개다. 입력을 받았다는 응답만으로 콘텐츠가 화면에 나왔다고 표시하지 않는다.

PC의 실제 HDMI 조작 화면에는 **선택한 앱에 키보드 입력 보내기** 선택 항목을 추가했다. 기본값은 꺼짐이다. 포인터 입력을 켜고 해당 항목을 선택한 뒤 콘텐츠를 클릭한다. ASCII 문자·편집 키·Ctrl+S를 보낼 수 있다. Esc는 조작을 취소하고 키보드 전달을 끈다. 색 선택 등 PC 화면의 입력란을 조작할 때는 앱으로 키를 보내지 않는다.

## 빌드와 검증

현재 소스는 v16c이므로 [README의 빌드 명령](README.md#build-current)을 따른다. 기존 RV32 도구 모음과 기준 이미지가 필요하다. 아래 `ui-examples-*` 결과 파일은 v14 당시 검사 기록이다.

PC 검사는 실제 편집·저장·다시 읽기, 문서 길이 제한, 글꼴, 설정, `/proc` 수집, 이벤트 격리와 큐 제한, 화면 변경 영역을 확인한다. 기존 이동·크기 조절·가림·취소·실패 복구 검사도 유지했다. 이미지 검사는 최종 SD 이미지의 RV32 실행 파일로 세 앱을 실행한다. 출력 장치 모형을 사용하므로 실제 투영 속도와 HDMI 지연은 측정하지 않는다.

검증 요약은 [ui-examples-validation.json](results/ui-examples-validation.json), 이미지 구성과 해시는 [ui-examples-image.json](results/ui-examples-image.json), 부팅 검사 결과는 [ui-examples-boot.json](results/ui-examples-boot.json)에 있다.

## 보드에서 실행하기

현재 v16c 이미지는 홈런처로 시작한다. 홈의 아이콘으로 앱을 열거나 콘솔에서 아래 명령으로 추가 창을 실행한다. v13에는 새 앱 입력 API가 없다.

```sh
/run/triangle-wm-runtime/triangle-examples editor --file /tmp/boayo-note.txt
```

다른 터미널에서 아래 명령으로 추가 창을 띄울 수 있다.

```sh
/run/triangle-wm-runtime/triangle-examples settings
/run/triangle-wm-runtime/triangle-examples dashboard
```

`--once`는 첫 화면을 게시한 뒤 종료하는 실행 검사 옵션이다. `--render /tmp/editor.ppm`은 앱 픽셀을 파일로 만들어 PC에서 확인할 때 쓴다. 이 파일은 보드 화면 캡처가 아니다.

현재 이미지 경로는 `D:\temp\haebancheon-keyboard-v16c\HAEBANCHEON-keyboard-v16.img`다. 이미지와 원본 로그는 Git에 넣지 않는다. v14 당시 이미지와 측정 계획은 도입 기록으로 보존하며, 현재 실보드 결과는 [README](README.md)를 참고한다.
