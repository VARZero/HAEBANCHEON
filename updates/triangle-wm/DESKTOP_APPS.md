# 홈런처·제어센터·터미널

v15에서 추가한 홈런처·제어센터·터미널을 설명한다. 현재 보드 적용본 **v16c**에 포함돼 있다. 2026-11-27 홈 화면 복귀, 홈의 창 버튼 숨김, 실제 PTY 터미널을 UART·HDMI로 확인했다. 아래 v15 이미지·검증 기록은 도입 당시의 PC·QEMU 결과다. 최신 빌드와 실보드 기록은 [README](README.md)를 참고한다.

## 홈런처

새 이미지로 부팅하면 기본 데모 대신 홈런처를 띄운다. 문서 편집기·설정·대시보드·제어센터·터미널 아이콘을 누르면 별도 프로세스와 창으로 실행한다. 실행 파일은 RAM의 `/run/triangle-wm-runtime/`에 둔다. 실행 접수 메시지는 실행 파일이 시작됐다는 뜻이며, 첫 화면 게시 완료를 뜻하지 않는다.

앱을 닫으면 그 아래에 남아 있던 홈런처가 다시 보인다. v16c에서는 홈런처 바깥의 닫기·이동·크기 조절 버튼을 숨긴다. Home 키는 기존 홈 화면을 앞으로 가져오거나 홈런처를 실행한다. 대시보드는 홈의 Dashboard 아이콘으로 실행한다. 별도 앱 전환기는 아직 없다.

등록 파일은 저장소의 [`config/apps.json`](config/apps.json), 이미지 안에서는 `/etc/boayo/apps.json`이다. 아이콘과 명령을 이 파일 하나에서 바꾼다. 수정한 뒤 홈의 **Reload**를 누르면 다시 읽는다. 잘못된 파일을 읽으면 기존 목록을 유지하고 오류를 표시한다.

```json
{
  "version": 1,
  "apps": [{
    "id": "terminal",
    "title": "Terminal",
    "color": 255,
    "command": ["@examples", "terminal"],
    "icon16": [
      "0000", "7FFE", "4002", "4002",
      "5002", "4802", "4402", "4202",
      "4402", "4802", "501E", "4002",
      "4002", "7FFE", "0000", "0000"
    ]
  }]
}
```

- `icon16`: 16×16 비트맵. 각 행을 4자리 16진수로 쓰며, 맨 왼쪽 픽셀은 최상위 비트다. 켜진 픽셀을 `color`의 RGB332 색으로 그린다. 화면에는 3배인 48×48픽셀로 표시한다.
- `command`: 실행 파일과 인자의 배열. `@examples`는 현재 실행 중인 예제 실행 파일의 절대 경로로 바뀐다. 다른 프로그램은 절대 경로를 쓴다. 공백·세미콜론 등을 셸 문법으로 해석하지 않는다. 셸 문법이 필요할 때만 `/bin/sh`, `-c`, 명령문을 명시한다.
- `title`: 현재 글꼴에 맞춰 ASCII 1–14자. 목록은 최대 24개, 한 페이지에 6개다. 파일 크기는 최대 64 KiB, 명령은 최대 32개 인자·총 8 KiB다.
- 다른 파일을 쓰려면 `--apps /경로/apps.json`이나 `BOAYO_APPS`를 지정한다.

실행 오류는 홈의 상태 줄에, 시작한 앱의 출력은 `/tmp/triangle-launcher-apps.log`에 남긴다. 홈을 닫아도 이미 실행한 앱을 함께 종료하지 않는다.

## 제어센터

큰 버튼 두 개만 둔다. 배경 흐림 효과나 장식 합성은 추가하지 않았다.

**센터 재지정**은 출력 시점을 정면 **yaw 0°, pitch 0°**로 되돌린다. 창의 저장 좌표를 옮기지 않는다. 내부적으로 기존 제어 소켓의 `view_set`을 호출한다. 진행 중인 창 조작은 기존 시점 변경 규칙에 따라 취소한다.

**전원 종료**를 처음 누르면 확인 상태가 된다. 5초 안에 같은 버튼을 다시 누르면 `/sbin/poweroff`를 실행한다. 다른 영역을 누르거나 시간이 지나면 취소한다. 미저장 문서를 자동 저장하지는 않는다. 상태 줄의 `Shutdown requested`는 종료 요청을 시작했다는 뜻이며, 전원이 실제로 꺼졌다는 확인은 아니다.

PC·QEMU의 모의 WM에서는 전원 종료 실행을 차단한다. 이번 검증에서는 실제 종료 명령을 실행하지 않았다. 제어센터는 신뢰하는 시스템 앱으로서 기존 제어 소켓과 보드의 실행 권한을 사용한다. 새 권한 분리 서비스는 추가하지 않았다.

## 터미널

2026-11-27 v16c 실보드에서 PTY 셸의 파일 쓰기, `tty`, `uname -r` 실행과 HDMI 출력을 확인했다. 실제 장치는 `/dev/pts/0`이었다. 문자 전달에는 기존 앱 입력 API를 사용했다. [검사 결과](results/home-caption-board.json)를 참고한다.

현재 `boayo-input`의 UART·SPI 키 탐색 경로는 Home·방향키·Enter 여섯 키만 전달한다. 아래의 일반 문자·특수키 입력은 앱 입력 API와 PC 입력 연결의 기능이다. 새 콘솔·HDMI 중계의 여섯 키 버튼만으로는 셸 명령을 타이핑할 수 없다.

명령을 흉내 내는 화면이 아니라 **PTY에 연결한 `/bin/sh -i`**를 실행한다. 현재 보드 사용자 권한으로 동작한다. 커널의 `CONFIG_UNIX98_PTYS`와 `/dev/pts` 마운트가 필요하며, 준비한 이미지에서 확인했다.

- 54열×18행, ASCII. 셸에 같은 터미널 크기를 전달한다. 창 크기 조절은 현재 고정된 콘텐츠를 확대·축소하며, PTY의 행·열 수를 바꾸지는 않는다.
- 입력·Backspace·Delete·방향키·Home/End·Tab·Enter를 전달한다. PC 입력 연결에서 Ctrl+C는 중단, Ctrl+D는 EOF, Ctrl+L은 화면 정리다. 위쪽 **INT**, **ESC** 버튼도 쓸 수 있다.
- PageUp/PageDown은 최대 200줄의 이전 출력을 살펴본다. 새로 입력하면 현재 출력으로 돌아온다. Esc 키 자체는 PC 연결의 조작 취소에 쓰므로 셸로 보내려면 ESC 버튼을 누른다.
- 줄바꿈·스크롤·커서 이동·줄/화면 지우기·기본 ANSI 색·스크롤 범위·대체 화면 일부를 처리한다. `TERM=vt100`, `LC_ALL=C`로 실행한다. 완전한 xterm 호환, 한글·유니코드·IME·마우스 보고·모든 전체 화면 프로그램의 동작은 보장하지 않는다.
- 입력 대기와 출력 읽기에는 상한을 두었다. 출력은 한 번에 최대 64 KiB를 읽고 최신 화면을 한 번 그린다. 출력이 더 밀리면 PTY의 흐름 제어에 맡기며, 데이터를 임의로 버리지 않는다. 보드에서의 처리량과 반응 속도는 아직 측정하지 않았다.
- 창을 닫으면 PTY를 닫고 셸을 정리한다. 셸이 종료되면 마지막 출력과 종료 코드를 남긴다.

PC의 실제 HDMI 입력 화면에서 **선택한 앱에 키보드 입력 보내기**를 켜고 터미널 콘텐츠를 클릭한 뒤 입력한다. 이 선택 항목은 기본으로 꺼져 있다. 브라우저 조작 모형의 터미널은 실제 명령을 실행하지 않는다.

## 빌드와 검증

현재 v16c는 [README의 빌드 명령](README.md#build-current)을 따른다. 여섯 키 입력과 새 커널을 포함한 절차는 [키 입력 문서](KEYBOARD.ko.md#빌드와-검사)에 있다.

아래 목록과 `desktop-apps-*` 결과 파일은 v15 도입 당시의 검사 기록이다.

기존 이동·크기 조절 검사에 더해 다음 항목을 확인했다.

- 기존 그리기·입력·취소·화면 공유 동작 유지.
- 잘못된 앱 목록과 실행 실패 처리, 명령 인자 보존.
- 실제 홈 클릭 → 별도 앱 창 생성·닫기.
- 출력 시점을 바꾼 상태에서 제어센터 클릭 → 0°·0° 복귀.
- 실제 PTY 명령, 행·열 수, Ctrl+C, 셸 종료·정리.
- ANSI 파서의 긴 입력과 200줄 제한을 메모리 검사와 함께 확인.
- 최종 이미지의 RV32 실행 파일로 홈 자동 시작·여섯 앱·실제 셸 명령 실행.

검사 기록은 [desktop-apps-validation.json](results/desktop-apps-validation.json), [desktop-apps-image.json](results/desktop-apps-image.json), [desktop-apps-boot.json](results/desktop-apps-boot.json)에 있다. 에뮬레이터 시간은 실보드 지연시간으로 사용하지 않는다.

## 보드 실행

현재 이미지의 로컬 경로는 `D:\temp\haebancheon-keyboard-v16c\HAEBANCHEON-keyboard-v16.img`다. v15 당시 이미지·로그는 도입 기록으로 보존했다. 현재 보드 검증과 이미지 검증 범위는 [README](README.md)에 구분했다.

홈에서 앱을 열어 확인한다. 콘솔에서 따로 실행할 수도 있다.

```sh
/run/triangle-wm-runtime/triangle-examples launcher --apps /etc/boayo/apps.json
/run/triangle-wm-runtime/triangle-examples control
/run/triangle-wm-runtime/triangle-examples terminal
```

기존 데모로 시작하려면 `TRIANGLE_START_APP=demo triangle-fixed-start start`를 쓴다. 이미 WM이 실행 중이면 먼저 종료한 뒤 시작한다. 홈을 포함한 실행 앱이 모두 종료될 수 있으므로 필요한 문서를 먼저 저장한다.
