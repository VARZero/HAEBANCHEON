# HAEBANCHEON — BoAYO 앱 갱신·합성 시간 개선 v10

`boayo-dirty-v9`를 보존하고 소프트웨어만 분리 수정했다. 기존 L1I/D 각 16KiB·2Way, DMA 3개 비트스트림, Linux 드라이버, 투영 계획·그림 에셋을 사용한다. RTL·MIG·HDMI IP는 변경하지 않았다.

## 변경 사항

- 앱 처리, 그림 선택, 그림 전달, 버튼 배치, 작업 공간, 합성의 준비·전송·투영·경계 합성·출력 전환·마무리, 상태 스냅샷 시간을 분리 계측한다.
- 창 위치·크기가 같으면 공통 버튼의 삼각함수 계산을 재사용한다. 숨김/복원/이동/크기 변경에는 다시 계산하고, 버튼 강조·입력 처리는 계속 수행한다.
- 앱의 열린 창·보관된 창 개수는 필요한 정보만 읽는다. 이 개수를 얻으려고 전체 상태와 포인터 판정을 생성하지 않는다.
- 작업 공간과 상태 조회는 포인터 판정만 캐시한다. 위치, 순서, 크기, roll, shape, mapped/input_enabled, surface 크기, decorated를 정확히 비교한다. 픽셀 내용만 바뀌면 판정을 재사용하고, 버튼·캡처·스크롤·포커스·세대 번호 등 공개 상태는 항상 새로 만든다.
- 합성에서 배치가 같은 창의 타일 집합과 변경 영역 목록을 재사용한다. 텍스처 부분 업로드·DMA·투영·빈 타일 메타데이터 처리는 유지한다.
- 2fps는 **프레임 시작 간 최소 0.5초**로 적용한다. 앱·합성·상태 처리로 소비한 시간도 간격에 포함된다. 처리 시간이 길면 다음 프레임을 추가 0.5초 대기 없이 시작한다. 지난 프레임을 몰아서 실행하는 큐는 만들지 않는다.

## 계측 사용법

`BOAYO_PROFILE=1`로 데몬을 시작하고 `boayo-native profile`로 누적 카운터와 성능 스냅샷을 읽는다. 기본 계측은 꺼져 있다. 매 프레임 콘솔 출력, 픽셀 재읽기, 전체 장면 검사는 추가하지 않았다.

각 카운터 배열은 `[경과 마이크로초, 작업 스레드 CPU 마이크로초, 호출 수]`이다. 두 스냅샷의 차이를 완료 프레임 수 차이로 나누면 프레임당 비용을 얻는다. 부모·자식 구간은 중첩되므로 `apps`, `compose`, `state_publish`와 그 내부 구간을 전부 합산하지 않는다. 첫 프레임의 사전 제작 실행 경로는 일반 갱신 경로와 다르며, 아래 비교는 초기화를 마친 Telemetry 반복 갱신이다. 상태 스냅샷에 포함된 `state_publish`는 현재 스냅샷 생성 직전까지의 누적 값이다.

상태 조회는 기존처럼 완성된 스냅샷을 반환한다. 계산 중 응답 가능한 상태이며, 진행 중 프레임의 중간 결과를 완료로 보고하지 않는다.

## 검증 재현

```sh
bash software/boayo/native/build.sh /var/tmp/haebancheon-frame-v10/final-host2 host
bash software/boayo/native/build.sh /var/tmp/haebancheon-frame-v10/final-rv32-2 rv32
bash software/boayo/native/build.sh /var/tmp/haebancheon-frame-v10/sanitize sanitize
bash tests/run_regressions.sh
bash tests/run_sanitize.sh
```

기본 경로는 기존 v9 호스트 실행 파일 및 v7 에셋/계획을 비교 대상으로 한다. `BASELINE_BINARY`, `CANDIDATE_BINARY`, `SANITIZE_BINARY`, `ASSETS`, `PLANS`로 경로를 지정할 수 있다. 빌드는 소스 스냅샷과 해시 명세를 남긴다. 테스트는 지정한 실행 파일의 빌드 명세에서 해당 소스·오브젝트를 선택한다.

통과한 검증:

- 기존 장면/동작/에셋 없는 경로/앱 갱신/버튼 생명주기 **120개 장면**의 픽셀 일치.
- 최소화·같은 위치 복원·다른 위치 복원·포커스·버튼 강조·닫기 상태 일치.
- 포인터 판정 캐시의 **248개 공개 상태** 원본 비교. 좌표·배치·입력 변화 시 무효화와 픽셀 전용 변화 시 재사용.
- 텍스처 풀의 무작위 조합 100회, CPU 부분 편집 60회, 건너뛴 갱신, 다중 창, 퇴출·실패 복구.
- ASan/UBSan 상태 캐시·텍스처 풀 검사.
- 실제 worker의 2fps 주기와 650ms 합성 지연 주입. 합성 후 500ms를 다시 기다리지 않음.
- 시점 재생, 상태 조회, 동시 수정 거절, 자동/명시 종료, 연결 해제 복원.

호스트 Mock 검증을 FPGA 성능·실제 HDMI 검증으로 취급하지 않는다. 실보드 측정 및 산출물은 `evidence/`에 별도로 기록한다.

## 실보드 구간 측정

2026-11-14 PZ-A7200T-KFB에서 같은 커널·SD·비트스트림으로 측정했다. v9의 동작은 그대로 둔 계측 전용 실행 파일과 v10을 각각 `/tmp`에 복원해 실행했다. 두 경우 모두 `BOAYO_PROFILE=1`, Telemetry 단독 실행, 초기화 이후 반복 갱신이다. v9는 6프레임, v10은 9프레임의 누적 카운터 차이다. 짧은 측정이며 임의의 모든 장면 성능을 보장하지 않는다.

| 항목 | 계측 v9 | 계측 v10 |
|---|---:|---:|
| 전체 갱신 간격 | 6.069초 | 3.727초 |
| 앱 처리 전체 | 2.591초 | 0.809초 |
| 앱 내부: 버튼 배치 | 0.521초 | 0.023초 |
| 앱 내부: 작업 공간 | 0.870초 | 0.479초 |
| 합성 전체 | 1.964초 | 1.782초 |
| 합성 내부: 레이어 준비 | 0.243초 | 0.213초 |
| 합성 내부: 타일 준비 | 0.248초 | 0.228초 |
| 합성 내부: 텍스처 전송 | 0.140초 | 0.116초 |
| 합성 내부: descriptor 준비·전송 | 0.063초 | 0.048초 |
| 합성 내부: 투영 실행·대기 | 0.110초 | 0.109초 |
| 합성 내부: 경계 합성 요청 | 0.453초 | 0.406초 |
| 합성 내부: 출력 전환 | 0.301초 | 0.313초 |
| 합성 내부: 마무리·통계 | 0.300초 | 0.239초 |
| 상태 스냅샷 게시 | 1.420초 | 1.167초 |

전체 간격은 **38.6% 감소**, 앱 처리 시간은 약 **68.8% 감소**했다. 상태 게시에는 조회 연결 종료 후 게시도 포함돼 프레임당 호출 수가 각각 1.167/1.111이다. 전체 간격은 완료 상태 스냅샷의 시간 차이로 산출한 값이며 HDMI 광학 지연 측정은 아니다. 실측에서 투영 실행 자체보다 CPU의 앱·상태 처리와 합성 부가 작업 비용이 크다.

v10의 추가 30초 대기 구간은 9회 갱신, 약 3.870초/갱신, 38,400바이트/갱신의 부분 업로드, 전체 업로드 추가 0회였다. DMA·앱·합성 오류는 0이다. 구간별 표와 대기 구간은 서로 다른 표본이다.

계측을 끈 일반 실행의 40초 대기 구간에서는 **13회 갱신, 평균 3.339초/갱신**을 확인했다. 실제 두 완료 스냅샷의 시간 차이는 43.404초다. 부분 업로드 13회, 전체 업로드 추가 0회, 평균 업로드 36,677바이트/갱신이었다. 앱·합성·DMA 오류와 DMA timeout은 0, 에셋의 CPU RGB 변환 횟수도 0이었다. 기본 계측은 계속 꺼 둔 채 `/tmp/boayo-frame-v10`을 실행 중이다.

실제 USB HDMI 캡처에서 Telemetry와 공통 버튼, 두 시점의 막대 길이 변화를 확인했다. `evidence/board-20261114/telemetry-normal-a.png`와 `telemetry-normal.png`가 원본 캡처이며 각 캡처 시각을 함께 보존했다. 기존 글자·가장자리의 거친 표시나 색 번짐은 이번 수정으로 해결했다고 판정하지 않았다.

**2fps는 상한이다.** 대기 주기를 바로잡았다는 뜻이며, 현재 처리량이 실제 2fps에 도달했다는 뜻은 아니다. 남은 주요 비용은 합성(경계 마스크 처리·전환·CPU 준비)과 상태 스냅샷 구성이다.

## 산출물 및 적용 범위

- 소스: `software/boayo/native/src/`. 변경한 기존 파일은 `apps.cpp`, `apps.hpp`, `resident.cpp`, `runtime.cpp`이며 `profile.hpp`, `frame_pacer.hpp`, `state_cache.hpp`를 추가했다.
- 일반/ASan·UBSan/RV32 빌드의 소스 40개가 동일함을 `evidence/source-consistency.json`에서 확인했다.
- 보드용 실행 파일: `D:\temp\haebancheon-frame-v10\boayo-native-v10`.
- 실행 파일 SHA-256: `02defaf14b975b9fcd0e155b12b7d1937618e16a0dd2927889430266bf8adf16`.
- 계측 기준 소스와 빌드 명세도 `evidence/`에 보존한다. 전송 및 재구성 시 길이·FNV 검사를 통과했다.
- SD와 `/usr/bin/boayo-native`는 v9 그대로다. 보드의 `/tmp/boayo-frame-v10`은 RAM 임시 실행 파일이므로 전원을 끄면 사라진다. 기존 `boayo-start`는 v9를 실행한다. 이번 작업에서 새 SD 이미지를 제작하거나 RTL 합성·배선을 다시 수행하지 않았다.
