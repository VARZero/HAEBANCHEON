# tiles-v2 변경 및 검증 범위

## 수정 사항

- ResidentCompositor에 요구 타일 버전 및 버퍼 A/B 저장 버전을 추가했다. 변경 없는 활성 타일만 필요한 시점에 복사한다.
- 연속 소영역 갱신에서 최초 필요한 타일 복사 이후 복사·메타데이터 쓰기가 0이 되는지, 숨김/재등장에서 투영·Fill·Copy 없이 이전 타일을 다시 사용하는지 별도 검증한다.
- 전환 후 즉시 타일·디렉터리 복제를 제거했다. 디렉터리는 목적지 버퍼와 다른 구간만 작성한다.
- 초기 빈 화면에서 Cell Data 앞 16바이트를 덮던 정렬 꼬리 쓰기를 제거했다.
- 명시적 단색 fill의 소스 수정 버전을 추적하고 전체를 덮는 타일은 DMA Fill을 사용한다. 다른 소스 수정은 해당 단색 표시를 무효화한다.
- 실제 드라이버의 bo_present가 마지막 전환 완료 메타데이터와 장면 길이에 따라 전체 로드/주소 전환을 선택한다. 기존 사용자 ABI와 하드웨어 ABI는 보존했다.
- 전환 완료까지 활성 버퍼 소유권을 유지하고 오류·시간 초과 뒤 재사용을 차단한다.

## 확인 방법

- 기존 렌더러와 42개 장면의 전체 유효 출력 결과 비교. 무변경, 내용 수정, 이동, 모양, 회전, 겹침, 숨김/재등장, 삭제, 포인터 및 반복 단색/이동 포함.
- 초기 DDR를 0이 아닌 값으로 채워 오래된 데이터 노출을 검사. 비활성 셀은 정상 렌더링에서 읽지 않는다. 전체 장면 결과 비교는 별도 테스트에서만 한다.
- 전환 후 복사 없음, 무변경 프레임 작업 없음, 최초 장면 반대 버퍼 복제 없음, 셀 데이터 변경 시 주소 전환, 메타데이터 쓰기 끝이 4,476워드를 넘지 않음을 검사.
- 실제 커널 공통 bo_present 함수로 메타데이터·팔레트·길이 변화, 최초 로드, 주소 전환, 범위 거부, 시간 초과 후 격리 및 늦은 완료 재사용 거부를 확인한다.
- 기존 BS25 RTL 직접 실행: 전체 로드 4,480워드, 주소 전환 시 메타데이터 전송 없음, 프레임 경계 이전 기존 장면 유지, 캐시 무효화, 비활성 검정, AXI 응답 지연, 메타데이터 오류 및 이후 재로드.
- 기존 DMA/소스 페이지/마스크 경계 검사, 호스트 기본 기능 9종을 자산 사용 여부별로 실행, ASan/UBSan, RV32 QEMU BusyBox/BoAYO 모형, 실제 SD 이미지 부트 페이로드 RTL, 커널·initramfs·ext4·앱·소스 해시 일치성을 확인한다.

## 검증 중 수정한 문제

재등장 재사용 시험에서 창 전체 수정 번호를 타일의 내용 식별에 쓰면, 작은 영역의 수정 뒤에도 나머지 타일이 재등장 시 다시 투영되는 문제가 드러났다. 창 전체 번호 대신 각 타일에 실제로 영향을 준 수정 번호를 기록하도록 고쳤다. 최종 소스와 이미지에 대해 재등장·부분 갱신 및 기존 기능 검사를 다시 실행한다. 이전 중간 이미지의 시험 결과를 최종 이미지의 통과 근거로 섞지 않는다.

RV32 QEMU에서 BoAYO 서비스 시작 시 SIGSEGV가 발생했다. 주소를 심볼로 대조하여 렌더링 worker의 스택 프레임에서 발생한 것을 확인했다. 타일 상태/내용 식별 배열을 포함한 ResidentCompositor를 worker의 지역 객체로 두던 것을 별도 메모리 소유 객체로 바꿨다. 전체 픽셀 버퍼를 새로 만드는 변경은 아니다. 최종 RV32 이미지로 서비스 시작·앱·입력을 다시 검사한다. 빌드는 동일 컴파일 옵션으로 독립 소스 파일을 최대 3개씩 컴파일하며 큰 스택 프레임 경고도 기록한다.

## 한계

실보드 속도·HDMI와 새 드라이버의 실제 예약 DDR 동작은 미확인이다. 기존 bitstream은 변경하지 않았다. 일반 알파 혼합 가속과 장애 뒤 무리셋 자동 복구는 추가하지 않았다. 타임아웃 시 안전하게 격리하며 보드 리셋이 필요할 수 있다. 기존 Linux clocksource의 pr_fmt 재정의 경고는 별도 기존 항목이다. 최종 PASS/FAIL과 정확한 산출물 해시는 동봉 증거를 기준으로 한다.
