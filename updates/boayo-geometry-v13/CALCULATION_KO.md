# 투영 계산 및 계측 설명

## 제외 검사

기존 계수식의 삼각형 꼭짓점 값 q0/q1/q2에 대해 affine 영역의 세 끝점은 `94q0+q1+q2`, `q0+94q1+q2`, `q0+q1+94q2`이다. 반전 항은 `q0-2q1+q2`다. 생성기는 각 그룹의 끝점 AABB와 반전 항 AABB를 따로 저장한다. 실행 시 투영의 다섯 평면 방향에 대해 각 AABB의 최대 내적을 구한다. 끝점의 최대치와 양의 반전 항 최대치의 합도 화면 평면 밖이면 그룹을 제외할 수 있다.

단, 장치가 사용하는 것은 정수화한 계수이므로 실수 경계만으로 제외하면 안 된다. 구현은 현재 고정 삼각형과 계수식의 크기를 상한으로 잡아 스케일에 따른 반올림 여유를 더하고, 부동소수점 계산 순서 차이 여유도 둔다. 작은 시야각과 큰/비정상 평면 값은 검사를 생략한다. 전체 후보를 남기는 것은 느려질 수 있지만 잘못 제외하지 않는 방향이다.

32개 그룹으로 빠르게 거른 뒤 4개 그룹으로 좁힌다. 그룹 배열은 `tests/generate_rejection_bounds.py --check`로 원본 고정 기하에서 재생성한 결과와 일치하는지 확인한다. 고정 기하를 바꾸면 반드시 경계 자료와 호환성 증거를 새로 생성해야 한다.

## 스케일

기존 식은 `2^min(22,floor(log2(2^29/max(bound,1e-30))))`다. 일반적인 정규화 양수의 `floor(log2(x))`는 double 지수에서 얻을 수 있다. 다만 라이브러리 log2 반올림이 거듭제곱 경계에서 결과에 영향을 줄 수 있어 mantissa 경계 양쪽 8192 이내와 비정규·예외 값은 원래 식을 사용한다. `memcpy`로 비트를 읽어 aliasing 위반을 피한다. 이 구현은 현재 host/RV32의 IEEE-754 double 환경을 대상으로 한다.

## 시간 해석

- `geometry_*_us_total`: 데몬 레이어 캐시 미스의 누적 실제 경과 시간. prepare, cull(후보 벡터 구성·reserve 포함), descriptor, insert(유효 타일 저장)를 구분한다.
- `mask_build_us_total`: 별도 경계 마스크 구간. 계수 시간에 합쳐서 보고하지 않는다.
- `profile` 배열: `[실제 경과 μs, 해당 스레드 CPU μs, 호출 횟수]`. compose 안에 layers/blend 등이 들어가므로 전 항목을 합산하면 중복이다.
- `BOAYO_MOTION_STEP.seconds`: 조작 요청부터 해당 출력 완료까지의 실제 시간. 비교용 프로필 출력은 이 시간을 기록한 뒤에 수행한다. 다음 단계까지의 전체 시험 소요 시간에는 UART 출력과 복구도 포함된다.
- 단계 10→11 누적 차이는 첫 창 이동을 포함한 구간이다. 배경 앱 갱신이 함께 진행될 수 있다. geometry_builds 4와 후보 개수로 이 구간의 새 배치 계산을 분리한다.
- `geometry_benchmark.cpp`: 데몬을 끈 상태에서 좌표 변환·계수식·스케일·인코딩을 분리한 배열형 작업이다. 출력 계수·표시 타일 순서·마스크 종류·패킹 비트를 두 경로에서 비교한다. masks_signature에는 검증용 결과 수집도 들어간다. 이 수치를 실제 창 조작 전체 시간으로 취급하지 않는다.

실행 중 프로필은 CPU 경합과 스케줄링의 영향을 받는다. 따라서 독립 벤치마크와 데몬의 수치를 직접 합치거나, 한 번의 실보드 측정으로 모든 창에서 같은 단축률을 보장하지 않는다.
