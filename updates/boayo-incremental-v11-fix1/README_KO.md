# HAEBANCHEON — v11 상태 갱신·드라이버 개선 및 본문 호버 수정

이 구성은 `boayo-incremental-v11`의 변경 항목 상태 갱신과 드라이버 최적화를 유지하고, 실보드에서 발견한 불필요한 CPU 그림 생성을 수정한다. RTL·비트스트림과 BOSIO 드라이버 소스는 v11과 같다.

## 실보드에서 발견한 문제

v11의 Telemetry 갱신은 정상 동작했지만, 세 창을 만드는 `motion` 요청은 120초의 응답 제한을 넘겼다. 상태 조회는 응답하되 창 상태는 오래된 스냅샷이었다. 작업 스레드의 실행 위치 8개를 잠깐 읽고 즉시 분리한 결과, `app_frame()`의 픽셀별 부동소수점 마스크 연산과 `nearbyintf` 등이 관찰됐다. 이 샘플만으로 전체 시간을 계산하지는 않는다.

입력 영역 `content`가 에셋 키에 그대로 포함돼 `app-base`와 `frame`을 모두 찾지 못하는 경우를 로컬에서 재현했다. 본문 호버의 그림은 중립 상태와 동일하지만 기존 에셋은 중립 상태를 빈 문자열 키로 저장한다. 기존 v11에서 이 경우 에셋 누락 2건이 발생했다.

`ui.cpp`에서 그림 선택용 호버만 정규화했다. 이동·크기 변경·닫기 버튼은 각각의 에셋을 유지하고, 그 밖의 영역은 중립 에셋을 공유한다. 포인터 이벤트·영역명·클릭·드래그 의미는 바꾸지 않았다. 준비된 그림이 실제로 없는 경우의 CPU 렌더링 기능도 유지한다.

## 검증

- 본문·바깥 영역·중립·세 버튼, 세 앱, 포커스 양쪽, 창 테두리/앱 전체를 조합한 **72개 픽셀 비교 일치**. 수정본의 해당 검사에서 에셋 누락·거부 0건.
- v11 대비 기존 **120개 장면** 회귀 통과: 일반 장면·앱 갱신·혼합 시점·이동/크기/닫기·에셋 없는 경로·공통 버튼 수명.
- 상태 캐시·텍스처 풀·프레임 주기·시점 서비스 회귀 통과.
- host/RV32 빌드 소스 일치, 설치 실행 파일·커널 initramfs·SD payload CRC·파티션·ext4·689개 에셋·37개 계획 검사 통과.
- 새 이미지의 QEMU Linux/BusyBox 셸·상위 DDR·BoAYO 자체 검사 통과. QEMU BOSIO는 Mock이며 실제 FPGA 또는 RTL 부팅 증거가 아니다.

실보드 정상 갱신은 평균 **2.529초/회**, 이전 v10 기록보다 **24.3% 단축**됐다. 다만 창 이동의 신규 마스크 CPU 계산이 오래 걸려 조작 시험은 10/25단계 후 중단했다. [실보드 결과와 미해결 병목](BOARD_RESULT_KO.md)을 참조한다. RAM에 올린 실행 파일 검증과 새 SD 전체의 실보드 콜드 부팅은 구분한다.

## 재현

`software/boayo/native/build.sh`로 host/RV32를 빌드한다. `tests/test_content_hover.py`에 v11 호스트 실행 파일, 수정 호스트 실행 파일, 에셋 디렉터리를 전달한다. 기존 `../boayo-incremental-v11/tests/run_regressions.sh`에 수정 빌드 디렉터리를 전달하고 `BASELINE_BINARY`를 v11로 지정한다.

`build_image.sh`는 Linux·루트 파일시스템을 별도 빌드 디렉터리로 복사하여 이미지를 생성한다. `tests/verify_build.py`와 `tests/test_image.py --boot-only`로 실제 산출물을 검사한다. 원본 v11 이미지와 그 실패 로그는 비교용으로 보존한다.
