# 2026-11-15 실보드 측정 결과

PZ-A7200T-KFB에서 기존 L1I/D 16KiB·DMA3 비트스트림을 다시 올렸다. FPGA DONE=1, CRC_ERROR=0, v11 Linux 커널·BusyBox 셸·SD ext4 `/data` 읽기/쓰기 마운트를 확인했다. 이후 같은 커널에서 fix1 실행 파일을 RAM에 적용했다.

## 실제 갱신 시간

정상 실행은 계측을 끄고 Telemetry 화면을 안정화한 뒤 두 상태 스냅샷 사이의 완료 횟수로 계산했다. 부팅 시간이나 광학적 HDMI 지연을 측정한 값이 아니다.

| 구성 | 완료 표본 | 갱신당 평균 |
|---|---:|---:|
| 이전 v10 정상 실행 | 13회 | 3.339초 |
| v11 정상 실행 | 18회 | 2.537초 |
| fix1 정상 실행 | 18회 | **2.529초** |

fix1은 이전 v10 기록 대비 **24.3% 단축**, 약 0.395회/초다. 2fps 상한에 도달하지 못했다. v10은 이전 부팅의 기록이고 짧은 표본이므로 정밀한 장기 벤치마크로 해석하지 않는다.

## 같은 v11 앱에서 드라이버 기존/개선 경로 비교

두 경로 모두 같은 선택적 계측을 켰다. 단위는 갱신당 ms이며 부모·자식 구간은 중첩되므로 합산하지 않는다.

| 구간 | 기존 경로 | 개선 경로 |
|---|---:|---:|
| 경계 합성 전체 | 605.1 | **370.7** |
| 출력 전환 처리 전체 | 298.4 | **155.5** |
| 드라이버 메타데이터 비교 | 153.7 | **24.2** |
| 경계 조각 DMA 시간 | 306.8 | **30.7** |
| 경계 조각 CPU 워드 처리 | 40.9 | 95.6 |
| 상태 게시 | 1101.9 | 1055.9 |
| 합성 전체 | 1901.7 | 1620.3 |

64바이트 이하의 짧은 연속 조각은 CPU의 정렬 워드 처리로 바꿔 DMA 호출 비용을 줄였다. 경계 조각 DMA 호출이 갱신당 약 160.7회에서 3.9회로 줄었다. 큰 조각은 DMA를 사용한다. CPU가 전체 장면을 다시 그리거나 장면 버퍼를 0으로 초기화하는 변경은 아니다.

출력 명령 MMIO는 약 0.28ms, 완료 폴링 읽기는 약 0.39ms, 폴링 사이 대기는 약 32.5ms였다. 이 장면에서는 하드웨어 완료 대기보다 CPU의 비교·합성 준비 비용이 컸다. 계측 자체의 비용도 있으므로 정상 실행 수치는 별도로 측정했다.

## 추가로 발견한 두 경로

1. **본문 호버 에셋 누락 — 수정 및 검증.** v11의 세 창 생성 요청이 응답 제한을 넘겼다. 실행 위치는 `app_frame()`의 소프트웨어 부동소수점 픽셀 처리였다. `content`를 별도 그림 키로 취급해 중립 에셋을 놓치는 경우를 재현했고, fix1에서 그림 선택만 정규화했다. 72개 픽셀 비교와 기존 120개 장면 회귀를 통과했다. 실보드에서 동일한 세 창 생성과 회전 10단계가 진행됐다.
2. **새 창 위치의 CPU 마스크 생성 — 미해결.** 25단계 조작 시험의 11단계(첫 창 이동)에서 수 분 동안 합성이 완료되지 않았다. 상태 조회는 살아 있었으며 실행 위치 표본은 `Compositor::prepare_masks()` → `shape_contains()` → JSON 수치 추출·소프트웨어 부동소수점 연산이었다. 시험 클라이언트를 잠깐 멈춰 진단한 뒤 시험을 중단했다. 이동·크기·앞뒤 순서·닫기까지 25단계를 실보드 통과했다고 보고하지 않는다. 로컬 픽셀 회귀 통과와 실보드 완료는 별개다.

이는 이번 드라이버 최적화로 해결된 완료 대기 문제가 아니다. 다음 최적화 대상은 새 기하의 마스크 계산에서 JSON 반복 해석과 픽셀별 부동소수점 비용을 줄이고, 실제 이동/크기 변경에서 사전 계산 결과를 재사용하는 것이다. 이 추가 최적화를 구현했다고 주장하지 않는다.

## 최종 보드 상태와 증거
