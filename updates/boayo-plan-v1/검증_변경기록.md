# plan-v1 변경·검증 기록

## 구현

- 기본 런처의 투영 목록·계수·모양 마스크를 PC에서 생성해 이미지에 포함한다.
- 소스 지문과 전체 키로 다른 배치나 이전 계산 자료의 재사용을 막는다.
- 누락·손상·불일치 자료는 기존 계산으로 복귀한다.
- 완전히 제외되는 타일의 투영을 생략한다. 이후 노출될 때 재투영하도록 무효화한다.
- 전체 유효 타일은 셀별 마스크 분기 대신 일괄 복사한다.
- 첫 프레임의 자료 로드·DMA 업로드·투영·합성·출력 단계를 추적한다.

## 개발 중 검사 수정

기존 Python 비교 테스트는 화면뿐 아니라 하드웨어 작업 수까지 동일하다고 가정했다. 빈 타일 작업을 제외하면서 작업 수 비교가 실패했다. 전체 장면과 갱신 패치의 픽셀 일치 검사는 유지했고, 작업 수는 기준 경로 이하인지 확인하도록 변경했다. 새 기본 런처 테스트는 정확히 96개 작업을 별도로 확인한다.

RV32 산술 결과를 UART로 읽는 검사에서는 종료 표식 뒤 줄바꿈 누락과 콘솔의 LF→CRLF 변환으로 검사 도구가 실패했다. 종료 표식을 수정하고 예상 바이트의 정확한 UART 인코딩과 비교하도록 고쳤다. 에코를 끈 명령의 반환 표식이 줄 시작이 아니라 응답 시작에 올 수 있는 경우도 검사기가 처리하도록 수정했다. 임의로 CR 문자를 삭제하거나 산술 오차를 허용하지 않는다. 이 문제로 대상 프로그램이나 커널을 변경하지 않았다.

최종 PASS는 재실행한 원본 로그와 `evidence/result.json`을 따른다.

## 남은 확인

- 실보드의 첫 화면 출력 시간, 실제 HDMI 캡처, 키 조작 응답 시간.
- 남아 있는 장면 버퍼 초기화·투영 결과 복사·CPU 타일 합성·출력 업로드의 구간별 시간.
- 임의 위치의 창이나 동적 모양은 CPU 계산을 유지한다. 하드웨어 계수·마스크 생성은 이번 범위에 포함하지 않았다.
- QEMU의 주변장치 모형과 SD 부트 RTL 검사는 전체 CPU RTL 및 물리 DDR/HDMI 검증을 대신하지 않는다.
