# HAEBANCHEON dirty-v9 실보드 갱신 비교 — 2026-11-14

PZ-A7200T-KFB에 기존 L1-16K/DMA3 비트스트림을 JTAG로 기록했다. DONE=1, CRC_ERROR=0. dirty-v9 Linux 쉘과 `/data` ext4 읽기/쓰기 마운트를 확인했다. 이번 실행에서 `/data` 파일 쓰기 시험을 추가로 수행한 것은 아니다.

## 실제 보드 비교

같은 SD·Linux·비트스트림에서 v8 실행 파일을 RAM에 임시 복원해 비교하고, 마지막에는 SD의 v9 실행 파일로 복귀했다. 조건은 런처에서 Telemetry 창 하나를 열어 주기적으로 내용을 갱신하는 경우다. 첫 적재와 비교 파일 전송·복원 시간은 측정 대상에서 제외했다.

| 항목 | v8 | v9 |
|---|---:|---:|
| 합성 시간 중앙값 | 4.873초 | 2.413초 |
| 관측 합성 시간 범위 | 4.141~6.119초 | 1.662~2.659초 |
| 전체 갱신 간격(근사) | 9.204초 | 5.457초, 복귀 재측정 5.412초 |
| 갱신당 직접 이미지 업로드 | 547,200바이트 | 38,400바이트 |
| DMA 오류 | 0 | 0 |

합성 시간은 약 50.5% 감소했다. 전체 갱신 간격은 약 41% 감소하여 약 1.7배의 갱신 처리율이다. 이미지 업로드는 약 93.0% 감소했다. v9의 약 32.5초 관측 구간에서 6회 부분 갱신, 전체 텍스처 재업로드 0회를 확인했다.

합성 시간은 앱 상태 갱신 비용을 제외한 기존 `last_compose_ms`다. 각 버전에서 상태 12개를 수집했고, 중복된 완료 프레임을 제거하면 v8 5개/v9 6개다. 전체 갱신 간격은 조회를 끊고 약 30초 기다린 전후의 완료 횟수와 캐시된 시간으로 계산한 근사치다. 모든 UI에서 같은 속도 향상을 보장하는 벤치마크는 아니다.

## UART와 HDMI

- UART 실시간 창과 USB3.0 Video HDMI 캡처 창을 열었다.
- 두 버전 및 복귀한 v9에서 앱 오류/렌더링 오류 없음, 출력코어 완료 응답과 DMA 오류 0을 확인했다.
- **HDMI 캡처는 검은 영상이다. 실제 UI 화면 표시 및 화질은 미확인이다.** 캡처를 다시 열어도 동일했고, 사용자에게 전원을 유지한 HDMI2 양쪽 재연결을 요청했다. 작성 시점에는 재연결 응답을 받지 못했다.
- 이전의 글자/테두리 표시 문제를 이번 시험으로 해결 또는 정상 판정하지 않았다.

## 시험 중 도구 문제와 처리

- BusyBox에 `sha256sum`과 `tail` 명령이 없어 해당 진단 명령을 바꿨다. 이미지 감사의 SHA-256, 보드 이미지 버전, 실행 파일 크기를 확인했고, RAM의 이전 바이너리 복원 시 원본/결과 FNV 검사도 통과했다. 보드에서 SHA-256 도구로 직접 해시를 읽었다고 주장하지 않는다.
- 이전 실행 파일 복원이 호스트의 180초 대기 한도를 넘었다. 같은 실행의 `PATCH_OK`와 종료 코드 0을 원본 UART에서 확인한 뒤 진행했다. 복원을 중복 실행하지 않았다.
- 데몬 정지 응답 직후 소켓 정리가 아직 끝나지 않아 이전 버전의 첫 시작이 거부됐다. 프로세스 종료와 소켓 제거를 확인하고 재시작했다. 이후 복귀 절차에는 소켓 제거 대기를 넣었다. 두 데몬이 장치를 동시에 사용하지 않았다.

`performance-comparison.json`에 원본 수치와 이미지/실행 파일/비트스트림 SHA-256을 기록했다. `v9-final-state.json`은 복귀 상태, `telemetry-final.png`는 실제 캡처의 검은 영상이다. 비트스트림 및 제품 RTL/소프트웨어 소스는 이번 측정에서 변경하지 않았다.

## HDMI 재연결 후 확인 — 23:19 KST

사용자의 HDMI 양쪽 재연결 후 캡처 프로세스가 I/O 오류로 종료된 것을 확인해 PC 캡처만 다시 시작했다. 보드 재부팅·비트스트림 재기록·BoAYO 재시작은 하지 않았다. Telemetry 창과 공통 창 버튼이 실제 HDMI 영상으로 보이며, 초록/파랑 막대 길이가 시간에 따라 바뀌는 것을 확인했다. `telemetry-reconnected-a.png`, `telemetry-reconnected-b.png`와 각각의 캡처 시각을 저장했다.

UART 재조회 시 누적 1,728회 합성, 1,726회 부분 업로드, 전체 업로드 5회, DMA·앱·렌더링 오류 0을 확인했다(`reconnect-uart.log`). 이는 조회 시점의 누적 상태이며 그동안 모든 프레임의 시각적 정확성을 검사했다는 의미는 아니다. 글자/테두리의 기존 거친 표현은 남아 있다. HDMI 화면 출력/막대 갱신 확인은 이제 완료했지만, 화질 문제 해결이나 전체 픽셀 정확도 검증으로 확대 해석하지 않는다.
