# BoAYO 변경 타일 직접 출력 — tiles-v1

## 목적

CPU가 전체 장면을 만들고 복사하던 기본 경로를 바꿨다. CPU는 창·이미지·작업 목록을 관리하고, 투영코어는 DDR에 결과를 쓰며, DMA는 필요한 타일만 복사한다. 빈 타일은 주소표의 빈 항목으로 표현한다. 기존 plan-v1은 보존했다.

**이번 결과물은 SD 이미지다. 보드 업로드·실행·HDMI 및 실제 속도 측정은 하지 않았다.** 이전 plan-v1 보드에서 전체 장면 할당·초기화가 약 214.3초 걸린 사실은 이전 버전의 측정이며 새 버전의 성능 수치가 아니다.

## 기본 실행 순서

1. 전용 DDR 예약 영역을 매핑한다. 이전 드라이버의 16MiB 전체 0 채우기를 하지 않는다.
2. 팔레트·타일 주소표만 설정해 빈 화면을 표시한다. 픽셀 영역은 읽거나 지우지 않는다.
3. CPU가 BoAYO 창 배치를 만들고, 고정 2D 이미지와 사전 계산 자료를 연결한다.
4. 변경된 타일을 구한다. 새 배치·이전 배치·겹친 창·포인터의 영향을 반영한다.
5. 고정 이미지는 기존 SD/Linux 파일 읽기 경로로 준비하고 원본 페이지 DMA로 투영용 DDR에 옮긴다. 같은 이미지가 남아 있으면 재사용한다. 파일 해석·페이지 관리는 CPU, 데이터 전송은 SD 컨트롤러/DMA가 담당한다.
6. 완전히 덮어쓰는 타일은 투영코어가 비표시 출력 버퍼에 직접 쓴다.
7. 부분적으로 덮는 타일은 필요한 타일만 배경을 준비한다. 사각형 범위만 있는 창은 기존 투영코어의 보존 쓰기를 사용한다. 둥근 모양 마스크는 임시 DDR에 투영 후 선택한 구간만 합성한다.
8. 새 주소표와 완성된 타일을 프레임 경계에서 표시한다. 다음 갱신을 위해 변경된 타일만 DMA로 반대 출력 버퍼에 맞춘다.

화면이 바뀌지 않으면 투영·픽셀 복사·표시 전환을 하지 않는다. 창 삭제로 빈 타일이 되면 주소표만 무효화하고 오래된 픽셀은 건드리지 않는다. 다시 사용하는 타일은 먼저 필요한 내용을 모두 작성한 뒤 공개한다.

## 기본 런처의 차이

| 항목 | plan-v1 | tiles-v1 기본 경로 |
|---|---:|---:|
| CPU 전체 장면 버퍼 | 4.14MiB, 초기화 | 없음 |
| CPU 출력 픽셀 사본 | 4.14MiB, 초기화·복사 | 없음 |
| CPU 유지 출력 자료 | 전체 장면 | 메타데이터 17.5KiB |
| 투영 결과 CPU 다운로드 | 수행 | 없음 |
| 투영 작업 | 96개 | 96개 |
| 전체 유효 타일 52개 | 결과 회수 후 CPU 합성 | 출력 DDR에 직접 투영 |
| 경계 타일 44개 | CPU 픽셀 합성 | 필요한 타일만 DMA 준비·선택 합성 |
| 빈 후보 타일 64개 | 투영 생략 | 투영·픽셀 초기화 모두 생략 |
| 드라이버 전용 DDR 초기화 | 16MiB 전체 지움 | 지우지 않고 예약 영역 매핑 |

경계 타일 44개에 필요한 첫 배경 준비는 합계 44KiB다. 전체 장면을 초기화하는 것과 다르다. 출력 버퍼 간 복사도 변경된 타일만 한다. 장면 전체를 CPU가 비교하거나 보관하지 않으며, 변경 여부는 창 상태·수정 영역으로 판단한다.

## 현재 IP로 가능한 경계 처리

기존 투영 IP는 임의 모양 마스크 합성기가 아니다. 비트스트림은 변경하지 않았다. 새 `BO_TILE_BLEND` 드라이버 명령은 1개 타일의 1비트 선택 마스크를 받는다. 연속된 전체 워드는 DMA로 복사/채우고, 4바이트 워드 일부만 바꾸는 경계는 커널이 그 워드만 읽고 수정한다. CPU의 전체 투영 결과 회수나 전체 타일 루프 합성으로 대체하지 않는다. 포인터도 같은 작은 마스크 명령으로 처리한다.

표시 중인 버퍼 쓰기, 타일·임시 영역 범위 초과, 잘못된 명령은 거부한다. DMA 오류 시 표시를 진행하지 않으며, 시간 초과는 기존 격리 정책을 따른다. BO_ABI3의 기존 명령은 유지하고 기능 비트 32와 명령 하나를 추가했다. 새 프로그램에는 새 커널 드라이버가 필요하다.

## 예약 DDR

DT의 `0xbd000000` 16MiB 영역은 `no-map`, `oryukdo,bosio-reserved-arena`로 전용 예약한다. 이 보드의 고정 주소와 크기, 물리/DMA 주소 일치를 검사한다. 이전 coherent pool과 같은 `MEMREMAP_WC` 속성으로 매핑하며 일반 메모리 할당자에 반환하지 않는다. 첫 화면 전 모든 메타데이터를 기록하며, 유효해질 타일은 작성 완료 후에만 주소표에 넣는다. 임시 투영 영역도 작업이 먼저 덮어쓰므로 통째로 지우지 않는다.

## 기능 범위와 비교 경로

기본 런처 및 Dashboard·Telemetry·Pulse, 이동·회전·크기·모양 변경, 창 겹침·숨김·삭제, WASD·클릭을 새 경로로 처리한다. 동적 2D 이미지 작성과 사전 계산되지 않은 창의 계수·마스크 계산은 CPU에 남는다. 전체 이미지가 아닌 변경 영역을 활용하되, 다른 창과 겹친 타일은 아래 창부터 다시 작성할 수 있다.

기존 CPU 렌더러는 `BOAYO_RENDERER=legacy`로 명시적으로 선택할 때만 사용한다. 기본 경로에서 지원하지 않는 장식 창, 가로 시야각 160도 이상, 외부 전체 장면 합성은 오류로 알린다. 몰래 전체 프레임 버퍼 경로로 돌아가지 않는다. 비교용 기존 경로에는 이전 전체 버퍼 처리가 남아 있으므로 일반 구동에서 선택하지 않는다. 일반 BoAYO 앱은 장식 없는 지원 범위의 창을 사용한다.

## 로컬 확인과 재현

검사 결과는 `evidence/`에 있다. 이전 CPU 합성 결과와 장면을 비교하며, DDR을 0이 아닌 값으로 채운 모형에서도 빈 영역·새 타일이 정확한지 확인한다. 커널 타일 합성 함수의 마스크·경계·활성 버퍼 금지·시간 초과 정책을 검사한다. 호스트 및 메모리 오류 검사, RV32 이미지 모의 부팅, SD 페이로드 RTL 검사를 포함한다. QEMU의 BOSIO와 RTL의 DDR은 모형이며 실보드 검증을 대신하지 않는다.

```sh
cd work/ORYUKDO-3d5i_BOSIO_SoC/updates/boayo-tiles-v1
bash build.sh /var/tmp/oryukdo-boayo-tiles-v1/release
bash validate.sh /var/tmp/oryukdo-boayo-tiles-v1
python3 package.py /var/tmp/oryukdo-boayo-tiles-v1 /mnt/d/temp/gen3bosio/boayo-tiles-v1
```

기존 Linux/OpenSBI/BusyBox 기반과 RV32 툴체인을 사용한다. 업데이트 ZIP은 기반 Linux 전체를 중복 포함하지 않는다. 새 RTL·Vivado 합성·배선·보드 업로드는 이 작업에 포함하지 않는다. 이전 커널의 clocksource `pr_fmt` 재정의 경고는 별도 기존 항목이다.
