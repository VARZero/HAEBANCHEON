# tiles-v1 변경 기록

## 실제 변경

- 기본 실행 경로를 DDR에 타일을 유지하는 방식으로 변경했다.
- CPU 전체 장면 버퍼와 전체 출력 픽셀 사본을 없앴다. CPU 출력 상태는 4,480워드 메타데이터다.
- 투영 결과를 CPU로 다운로드하지 않는다. 전체 유효 타일은 출력 DDR에 직접 투영하고, 마스크 타일은 임시 DDR에서 필요한 구간만 합성한다.
- 빈 타일은 메타데이터만 무효화한다. 변경 없는 화면은 투영·픽셀 복사를 하지 않는다.
- 필요한 부분 타일만 DMA로 배경을 준비하며, 출력 버퍼 간 복사도 변경된 타일에 한정한다.
- BO_TILE_BLEND를 추가했다. 연속 전체 워드는 DMA, 부분 워드 경계는 제한된 CPU 수정으로 처리한다. 기존 IP·RTL·비트스트림은 변경하지 않았다.
- 이 보드의 전용 no-map DDR 예약 영역을 기존 coherent pool과 같은 WC 속성으로 매핑해 16MiB 전체 초기화를 제거했다. 일반 RAM이나 다른 장치의 메모리 영역을 사용하지 않는다.
- 기본 렌더러에서 지원하지 않는 창은 명확히 오류를 알리고, 전체 버퍼 경로로 자동 전환하지 않는다. 기존 렌더러는 명시적 legacy 설정으로 보존했다.

## 확인

기존 plan-v1의 화면을 기준으로 17개 장면을 비교했다. 초기 DDR을 0이 아닌 값으로 채워 빈 타일이나 노출되는 영역이 이전 데이터를 보여주지 않는지 검사했다. CPU 장면 저장·결과 다운로드·출력 픽셀 업로드가 없는지 함께 검사했다. 커널의 실제 타일 합성 함수는 1,024개 마스크·색·복사 경우와 경계·활성 버퍼·시간 초과 처리를 확인했다.

첫 C 테스트 빌드에서 한 줄의 연속 if문에 대한 들여쓰기 경고가 오류로 처리됐다. 문장을 분리하고 재실행했다. 최종 소스에서 호스트/RV32/메모리 검사 빌드의 소스 지문이 일치하는지 확인한다. 최종 결과는 evidence/result.json과 원본 로그를 따른다.

## 아직 측정하지 않은 것

새 이미지의 실보드 부팅 시간·첫 화면 시간·HDMI·키 반응 시간은 측정하지 않았다. 전체 CPU RTL로 Linux부터 GUI까지 실행하지 않았다. QEMU와 SD/DMA RTL의 모형 검사는 실제 하드웨어 결과와 구분한다. 사용자의 요청에 따라 보드에 업로드하거나 실행하지 않는다.
