# HAEBANCHEON components-v6 검증·변경 기록

2026-11-14. 기존 v5와 실행 중인 실보드는 보존했다. 변경 범위는 BoAYO 사용자 프로그램, 에셋 제작·설치·검증 스크립트와 새 SD 초기 파일시스템이다. RTL와 Linux 드라이버는 변경하지 않았다.

## 해결한 문제

1. 런처 계획 하나만 초기 파일시스템에 넣던 설치 경로를 수정했다. 앱 기본 배치와 BoAYO 공통 버튼까지 37개 계획을 설치한다.
2. 실제 이동 버튼 높이 100에 맞는 공통 에셋을 추가했다. 이전의 40·80 높이만 준비되던 누락을 수정했다.
3. 앱 생성·포커스 변경·상태 갱신 때 전체 RGB 이미지를 그리고 복사하던 경로에 읽기 전용 기본 이미지와 작은 조각의 DMA 조합을 연결했다.
4. `App::present`의 전체 이미지 추출·비교·복사를 없애고, 미리 준비된 이미지 참조를 게시한다. 조각 원본의 수명과 DMA 순차 완료는 유지한다.
5. 에셋·계획 전수 검증은 제작 PC에서 수행한다. 손상 데이터, 일치하는 해시로 다시 서명된 잘못된 크기·마스크도 설치 전에 거부한다.
6. 앱 생성 응답만 성공으로 보지 않고, 새 출력 완료와 장면 내용을 검사하도록 테스트를 강화했다.

QEMU/장면 검사의 BOSIO는 Mock Backend다. 출력 캐시 RTL 검사와 SD·DMA RTL 검사는 각각 독립 시험이며, 전체 CPU RTL Linux 부팅이나 실보드 HDMI 시험으로 보고하지 않는다. 자세한 결과는 `evidence`의 원본 로그와 JSON을 따른다.

정해진 기본 배치에서는 CPU 기하 타일 계산, 경계 마스크 샘플 계산, 앱 RGB materialization 카운터가 모두 0인지 확인한다. 자유로운 이동·카메라 변경에는 기존 계산이 필요할 수 있다.

## 검사 중 조정

SD RTL 검사에 있던 고정 2억 사이클 제한으로 큰 이미지 시험이 먼저 시간 초과됐다. 하드웨어 오류 플래그는 발생하지 않았다. 테스트의 감시 제한만 실제 부트 페이로드 섹터 수에 비례하도록 수정했고, 같은 RTL에서 400,210,043사이클에 부트 페이로드 검증을 완료했다. 런타임 왕복까지 400,236,792사이클이었다. 초기 실패 로그도 보존한다. 이 사이클은 카드·DDR 모델 조건이며 실보드 부팅 시간으로 환산해 보고하지 않는다.

## 아직 확인하지 않은 부분

새 이미지의 실제 Linux 부팅 시간, 데몬 시작부터 첫 HDMI 화면까지의 시간, 실보드 다른 창 표시·이동·크기 변경 시간은 아직 측정하지 않았다. 필수 앱 에셋의 초기 파일시스템 포함으로 부팅 데이터가 증가했다. CPU 그리기 감소가 전체 콜드 부팅 시간 감소를 보장하지 않는다.

비표준 위치·크기·상태는 기능을 유지하기 위해 CPU fallback이 남아 있다. 지금 에셋 체계는 기본 앱과 공통 조작부를 빠르게 준비하는 구조이며, 모든 임의 UI를 하드웨어만으로 그리는 새 렌더러는 아니다.
