# tiles-v5 변경 및 검증 기록

비교 기준은 보존된 `boayo-tiles-v4`다. 이 후보는 해반천의 고정 첫 장면 요청을 제작 PC에서 사전 생성한다.

## 변경 파일

- `common.hpp`: 정상 검사 시 리터럴 오류 메시지의 동적 할당 제거.
- `plan.hpp`, `plan.cpp`, `ready_plan.py`: 장치 요청 형식, 읽기 전용 매핑, 외부 자료 검증, 독립 C++/Python 생성기.
- `resident.cpp`, `resident.hpp`, `backend.hpp`: 준비된 요청 배열 전달, 최초 장면 빠른 실행, 변경 타일 상태 보존, 전수 버전 검사의 선택적 진단화.
- `main.cpp`: 테스트 전용 준비 자료 내보내기와 실패 주입·상태 확인.
- 제작·설치·이미지 감사 도구: 요청 자료를 initramfs와 ext4에 포함하고 내용 일치 검증.

## 필수 증거

- `device-ready/`, `device-ready-sanitize/`: 독립 생성기 일치, 기존 경로와 첫 화면 동등성, 잘못된 요청 자료의 안전한 대체 실행, 7개 실패 주입 지점에서 불완전 전환 방지.
- `check-allocations.log`: 정상 검사 4,220회의 할당 0회, 실패 예외 유지.
- `resident/`, `resident-sanitize/`: 42개 장면의 픽셀 결과 동등성, 부분 업데이트·겹침·이동·삭제·포인터·버퍼 교대.
- `versions/`, `versions-sanitize/`, `versions-debug/`: 버전 재사용·버퍼 간 복사·가림 복원, 진단 검사 활성 경로.
- `build-plan-gate.log`: 서명값이 갱신된 잘못된 명령 자료도 제작 단계에서 거부.
- `artifact.json`: 빌드 소스, 실행 파일, initramfs, ext4, SD 페이로드의 일치.
- `qemu/`: Linux/BusyBox, 상위 DDR 검사, BoAYO Mock 실행, 앱·WASD·클릭·셸 복귀.
- `scene-rtl.log`, `sd-rtl.log`: 기존 출력 RTL과 SD 이미지 읽기/DMA 테스트. 실제 MIG 및 HDMI 물리 신호의 대체 검증이 아니다.

## 남은 확인

새 이미지의 실보드 실행 시간과 HDMI 영상은 미측정이다. RTL 변경이 없으므로 이번 후보용 Vivado 합성·배선은 새로 실행하지 않는다. 기존 비트스트림의 자원·타이밍 수치를 소프트웨어 최적화의 측정 결과로 다시 주장하지 않는다.

## 검증 실행기 후처리 기록

개별 이미지 감사·QEMU·두 RTL 테스트가 모두 완료된 뒤, 실행 중 추가한 요약 명령 때문에 기존 쉘 실행기가 마지막 종료문을 읽을 때 EOF 오류를 냈다. 현재 `build.sh`와 `validate.sh`는 `bash -n`을 통과했고, 누락된 프레임 요약은 완료된 원본 로그에서 별도로 생성했다. `package.py`가 QEMU·RTL·호스트·메모리 검사 결과와 실제 소스·실행 파일·이미지 해시를 다시 대조해 통과한 뒤 패키징했다. 원본 `validate-image.log`의 종료 오류는 지우지 않았다. 개별 테스트 PASS와 실행기 후처리 오류를 구분한다.

기준 커널의 `clocksource.c`에 있던 `pr_fmt` 재정의 경고는 유지된다. 이번 변경으로 새 커널 드라이버나 RTL을 추가하지 않았다.
