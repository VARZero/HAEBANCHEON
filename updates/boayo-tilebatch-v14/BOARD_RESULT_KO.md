# v14 실보드 부팅·화면·앱 갱신 비교 — 2026-11-16

**기능 실행은 확인했지만 성능은 회귀했다.** 같은 조건에서 Telemetry는 약 31.6%, SDK Pulse는 약 26.7% 더 오래 걸렸다. 이번 v14를 일반 앱 갱신 속도 개선으로 판정하지 않는다.

사용자가 v14 SD 기록·검증 후 전원을 켠 보드에서 기존 비트스트림을 업로드했다. PROGRAM 완료, CONFIG_DONE=1, CRC_ERROR=0을 확인했다. Linux 커널 `6.12.0-haebancheon-tilebatch14`, 이미지 식별 `HAEBANCHEON-BoAYO-tilebatch-v14`, `/data` ext4 마운트와 쉘 응답을 확인했다.

HDMI2에 연결된 `USB3.0 Video` 캡처로 런처와 Telemetry/Dashboard/SDK Pulse의 실제 화면을 확인했다. UART 수집 창과 HDMI 실시간 창을 PC에 열었다. 최종 상태의 DMA 오류·타임아웃·출력 오염 표시는 모두 0이다. ACK만으로 픽셀 전체 정확성을 주장하지 않으며, 캡처 화면의 관찰과 호스트의 픽셀 기준 검증을 구분한다.

## 같은 보드에서 직접 비교

기준 구현은 v13의 갱신·재사용 코드에 v14와 같은 사각형 본문 UI를 적용한 로컬 검증용 구현이다. 원래 v13 이미지 자체와의 비교는 아니다. 37개 투영 자료의 payload가 동일함을 확인한 뒤 기존 호환성 인터페이스로 v14 SD의 자료를 읽도록 했다. 기준 실행 파일은 RAM에만 올렸고 SD와 RTL은 변경하지 않았다. 비교가 끝난 뒤에는 SD의 v14 실행 파일을 구동했다.

같은 비트스트림·커널·드라이버·UI·투영 자료를 사용했다. 각 앱을 단독 실행하고 준비 후 약 60초 동안 관측했다. 양쪽 모두 상세 프로파일과 초기화 로그를 끈 상태다. 시작과 끝의 상태를 RAM 파일에 저장하고 측정 구간 이후 UART로 읽어 직렬 출력 간섭을 줄였다. 시간은 완료된 화면 수와 상태 스냅샷 시각의 차이로 계산한다. 아래 값은 앱 내용 갱신 간격이며 HDMI 신호의 주사율이 아니다. 각 작업·구현당 한 구간을 측정한 결과로, 여러 반복 실험의 신뢰구간은 아니다.

| 앱 | 최적화 전 기준 | v14 | 시간 단축률 (+가 개선, -가 악화) |
|---|---:|---:|---:|
| telemetry | 2.618초 (25회) | 3.444초 (21회) | -31.55% |
| sdk-pulse | 2.391초 (28회) | 3.029초 (22회) | -26.69% |

초기 v14 관측은 16회 평균 3.660초였다. 이전 날짜의 v11/fix1 2.529초와 직접 비교하면 조건이 달라 오해할 수 있어, 위의 동일 보드 비교를 추가했다. 초기 관측 자료는 `v14-normal.json`으로 별도 보관한다.

작은 에셋 반복 시험의 요청 수 87.5% 감소는 전체 앱 갱신 시간 87.5% 단축을 의미하지 않는다. 실제 효과는 캐시 적중·퇴출, 새로운 에셋 적재, 영역 정리 및 기존 합성 비용에 달려 있다. 이번 측정으로 창 이동·새 크기의 기하 계산 시간까지 개선됐다고 판단하지 않는다.

측정 구간의 캐시 동작은 Telemetry 적중 1회·새 적재 40회·퇴출 40회, SDK Pulse 적중 0회·새 적재 22회·퇴출 22회였다. SDK Pulse의 10종 막대는 각 38,400바이트로 합계 384,000바이트여서 최대 262,144바이트 에셋 캐시에 모두 남지 않는다. 이 경로에서는 원래 창으로 직접 올리던 자료를 캐시에 올린 뒤 다시 DDR 복사하는 작업이 매번 추가된다. 추가 복사·캐시 관리와 타일 변경 영역 관리의 개별 시간 기여도는 이번 계측을 끈 시험에서 분리하지 않았다. 개선하려면 이런 단발/순환 대형 자료의 캐시 적용을 피하고 작은 반복 자료에 집중하는 방향부터 검토해야 한다.

Dashboard는 입력이나 창 수 변화 없이 두면 표시 내용이 바뀌지 않는다. 이를 자동 갱신 앱으로 취급한 최초 측정 스크립트의 `n>0` 검사가 실패했다. 소프트웨어 정지로 판단하지 않고 `dashboard-idle.json`에 갱신 0회·앱/렌더 오류 없음으로 기록했다. Dashboard는 속도 비교에서 제외하고 자동 갱신하는 SDK Pulse로 대체했다. 시험 스크립트 실패와 보드 기능 실패를 구분한다.

## 화면이 정지했던 구간

비교용 프로그램을 준비하는 동안 BoAYO를 의도적으로 종료했다. UART 전송 후 RAM 실행 파일 복원에 약 63.91초가 걸렸고 `PATCH_OK`·반환 코드 0·쉘 프롬프트를 확인했다. 이 구간의 화면 정지는 보드 정지로 판단하지 않는다. 이후 앱을 다시 실행해 실제 화면 갱신과 위 측정을 완료했다.
