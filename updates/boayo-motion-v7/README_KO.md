# HAEBANCHEON — BoAYO motion-v7

시점의 피치·롤·요 혼합 회전과 창 이동·크기 변경·겹침·닫기를 실제 BoAYO 입력 경로로 실행하는 선택형 검증 모드다. `components-v6`의 고정 에셋과 DMA 조합 구조를 유지한다. 일반 부팅이나 BoAYO 시작 때 자동 실행하지 않는다.

## 보드에서 실행

새 `HAEBANCHEON-KFB-BoAYO-motion-v7.img`를 사용한다. 기존 `HAEBANCHEON-KFB-L1-16K-DMA3-v1.bit`를 그대로 사용하며 RTL·MIG·HDMI IP·Linux 드라이버는 변경하지 않았다.

Linux 셸에서 BoAYO가 실행 중이면 다음 명령을 입력한다. 실행 전에는 창 드래그나 버튼 누르기를 끝낸다.

```sh
boayo-motion
```

한 번의 25단계 검사다. 각 단계의 출력 완료를 기다리고 약 0.5초 유지한 뒤 진행한다. 3회 반복하고 단계마다 1초 유지하려면 다음처럼 실행한다.

```sh
boayo-motion 3 1000
```

중단은 `Ctrl+C`다. 다른 셸에서는 `/usr/bin/boayo-native motion-stop`을 사용할 수 있다. 이미 실행 중인 장치 요청이 끝난 뒤 복원하므로 즉시 모든 하드웨어 동작이 끊어지는 방식은 아니다. 정상 종료 시 시험용 창과 임시 드래그 안내 창을 정리하고 이전 시점·포커스·런처 표시 상태로 돌아간다. 기존 앱은 닫지 않는다. 장치 오류가 난 경우에는 복원 완료로 표시하지 않는다.

중복 실행은 거부한다. 두 번째 검증 명령의 실패가 첫 번째 실행을 종료시키지 않는다. 제어 연결이 끊겨도 해당 실행의 창을 정리하도록 연결했다.

## 25단계 내용

1. 기준 시점에서 요·피치·롤 각각의 양·음 방향을 확인한다.
2. **피치·롤·요가 모두 0이 아닌 자세**를 섞어서 적용한다. 회전 계수 180개를 기존 출력코어 포즈 인터페이스로 전달하고 프레임 경계 완료 응답을 기다린다.
3. Dashboard의 공통 **이동 버튼**에 누르기·방향 변경·떼기 입력을 보내 창의 방위각과 위도를 바꾼다. 반대 방향과 원위치도 포함한다.
4. 공통 **크기 조절 버튼**을 드래그해 가로·세로 각도 크기를 늘리고 줄인다.
5. Telemetry를 겹치고 Dashboard·Telemetry를 차례로 앞으로 가져온다. SDK Pulse도 이동하고 복원한다.
6. 혼합 시점에서 다시 관찰한 뒤 시점을 되돌린다.
7. SDK Pulse → Telemetry → Dashboard 순서로 **닫기 버튼에 클릭**을 보낸다. 창과 그 공통 버튼들이 제거되고 뒤쪽 장면이 드러나는지 검사한다.

창 위치는 방위각·위도, 창 크기는 가로·세로 시야각이다. 화면 시점 회전과 창의 공간 배치는 별개의 상태다. 이번 모드에서 창 자체의 롤을 조작하는 단계는 추가하지 않았다. 요청한 롤은 관찰 시점에 적용한다.

## UART 상태와 완료 판정

`BOAYO_MOTION_BEGIN`, 단계별 `BOAYO_MOTION_STEP`, 마지막 `BOAYO_MOTION_COMPLETE`가 출력된다. 단계 로그에는 단계명, 피치·롤·요, 소요 시간, 출력 완료 여부가 있다. `/usr/bin/boayo-native status`의 `motion`에서도 진행 상태를 볼 수 있다.

완료 판정은 명령 접수만으로 하지 않는다. 각 변경의 `target_generation` 이상을 실제 출력 처리한 `rendered_generation`이 확인돼야 다음 단계로 넘어간다. 카메라 포즈는 기존 드라이버가 프레임 경계 적용 완료를 기다린다. 모의 장치에서는 모의 완료, 실제 장치에서는 드라이버 완료 응답을 뜻하며 **캡처 영상의 픽셀을 자동 판독한 결과는 아니다.** 실제 HDMI 표시는 별도로 확인해야 한다.

임의 창 이동·크기 변경은 사전 제작하지 않은 기하 계산을 실행할 수 있어, 고정 첫 화면보다 느릴 수 있다. 완료 전에 다음 명령을 밀어 넣어 중간 화면을 건너뛰지 않는다. 이 모드는 연속 동작의 기능과 단계별 시간을 확인하기 위한 것이며, 일정 FPS를 보장하는 애니메이션이 아니다.

## 수동 시점 조작

기존 `boayo-keys`에서:

- WASD / 방향키: 피치·요
- Z / C: 롤 음·양 방향
- R: 세 축 모두 초기화
- Space / Enter: 중심 클릭
- Q: 키 입력 모드 종료

세 축을 한 명령으로 설정할 수도 있다.

```sh
/usr/bin/boayo-native view-set 8 -6 15
```

순서는 **요, 피치, 롤**, 단위는 도다. `view`는 상대 변화, `view-set`은 절대 자세다. 피치는 ±85도로 제한하고 요·롤은 정규화한다.

## 변경 범위와 검증

- `wm.cpp` → `Output::set_pose` → 기존 장치 포즈 요청까지 롤을 연결했다.
- `motion.hpp`가 실제 앱과 공통 버튼 입력을 조작한다. 앱별 닫기·이동·크기 조절 버튼을 별도로 구현하지 않았다.
- `runtime.cpp`에 출력 세대 확인, 실행·중단 명령, UART 단계 로그, Z/C 조작을 추가했다.
- 평상시 화면 경로에 전체 픽셀 검사나 새 로그 루프를 넣지 않았다.
- 기존 components-v6와 원본 Python 참조는 보존했다. 자세한 결과는 `검증_변경기록.md`, `evidence`와 전달 폴더의 `reports`에 있다.

로컬 검사는 호스트와 ASan/UBSan의 전체 시나리오, 기존 9개 회귀 그룹, 원본 Python과 혼합 자세 계수 비교, 새 이미지의 RV32 QEMU 실행, 기존 SD·출력 캐시 RTL 검사를 포함한다. QEMU의 BOSIO는 Mock Backend다. 전체 CPU RTL의 Linux 부팅, 실보드 25단계 동작, HDMI 영상 판독은 별도다.

## 재현

WSL Ubuntu와 기존 L1/DMA3 Linux 기준 빌드·RV32 툴체인을 사용한다.

```sh
bash build.sh /var/tmp/haebancheon-motion-v7
bash validate.sh /var/tmp/haebancheon-motion-v7
```

`tests/test_motion.py`는 실제 서비스 소켓과 CLI를 사용해 이동·크기·닫기·중단·복원을 검사한다. `tests/test_pose.py`는 WM을 통과한 장치 회전 계수 4,680개를 원본 Python 결과와 정확히 비교한다. `tests/test_motion_image.py`는 만들어진 SD의 실제 Linux 페이로드를 RV32 QEMU에 적재하고 동일 `boayo-motion` 명령을 실행한다. SD 부트로더 검사는 이와 별도의 RTL 시험이다.
