# HAEBANCHEON motion-v7 검증·변경 기록

2026-11-14. components-v6를 보존하고 별도 구성에 추가했다. 실보드의 실행·UART·HDMI 창과 비트스트림은 이번 작업에서 조작하지 않았다.

## 추가한 기능

- 시점 피치·롤·요의 동시 설정과 상대 변경. 기존 출력코어의 180개 회전 계수 인터페이스 사용.
- 실제 Dashboard·Telemetry·SDK Pulse와 BoAYO 공통 버튼을 이용한 25단계 자동 시나리오.
- 방위각·위도 이동, 가로·세로 각도 크기 변경, 겹침과 포커스 전환, 공통 닫기 버튼으로 세 창 제거.
- 실행 반복 횟수와 단계 유지 시간 지정, Ctrl+C·별도 중단 명령, 연결 종료 시 정리.
- 시험용 창·드래그 안내 창만 정리하고 기존 앱과 시점·포커스·런처 상태 복원.
- 창 변경의 목표 세대와 실제 출력 처리 세대를 비교해 단계 순서를 보장. 포즈는 드라이버의 프레임 경계 적용 응답 확인.
- 완료 대기는 작은 `motion_progress` 응답만 사용한다. 정상 대기 중 전체 상태 JSON 직렬화나 전체 픽셀 검사를 반복하지 않는다.
- 수동 키 입력에 Z/C 롤 회전 추가. WASD·중심 클릭·R 초기화·Q 종료는 유지.

| 화면 내용 | 시작 장면 + 25단계의 전체 장면 데이터가 보존한 v5 렌더러와 정확히 일치 |

| 산출물 | 최종 소스·빌드 바이너리·커널 내 파일·에셋·계획·ext4·이미지 SHA 일치 확인 |

**QEMU에서 BOSIO는 Mock Backend다.** 회전 계수 비교는 소프트웨어 계산과 장치 요청 연결의 검사이며, 실제 HDMI 화면을 캡처해서 비교한 검사가 아니다. 출력 캐시 RTL 검사 역시 전체 HDMI 경로가 아니다. 실제 보드에서 혼합 회전·창 이동·크기 변경·닫기를 눈으로 확인하고 단계별 시간을 측정하는 일은 남아 있다.

창의 임의 이동·크기 변경에서는 기존 CPU 기하·마스크 계산 경로가 사용될 수 있다. 고정 첫 화면의 사전 제작 경로와 같은 속도를 보장하지 않는다. 검증이 출력 완료를 기다리므로 느린 단계를 건너뛰지 않는다. QEMU 실행 시간을 실보드 성능으로 보고하지 않는다.

## 검증 중 보완한 내용

- 드래그가 생성한 숨겨진 안내 창이 남는 것을 확인해 시험 종료 시 함께 정리했다.
- 중복 CLI의 오류 정리가 먼저 실행 중인 다른 검증을 중단하지 않도록 소유권 확인을 추가했다.
- 중단 직전에 눌린 입력이 남지 않도록 해당 실행의 입력만 해제한다.
- 완료 조회를 전체 상태 응답에서 작은 진행 응답으로 바꿨다. 최종 이미지로 다시 검사했다.

RTL·MIG·HDMI IP·Linux 드라이버·DMA 하드웨어 변경은 없다. 기존 `HAEBANCHEON-KFB-L1-16K-DMA3-v1.bit`와 새 `HAEBANCHEON-KFB-BoAYO-motion-v7.img`를 사용한다. 이미지의 최종 크기와 SHA256은 동봉한 `manifest.json` 및 `SHA256SUMS.txt`가 기준이다. 원본 결과는 `evidence`와 전달 폴더의 `reports`에 보관한다.
