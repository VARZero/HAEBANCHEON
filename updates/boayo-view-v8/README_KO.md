# HAEBANCHEON — BoAYO 연속 시점 미리보기 v8

기존 motion-v7을 보존하고 추가한 소프트웨어 변형이다. RTL, 비트스트림, Linux 드라이버, SD 부팅 이미지는 변경하지 않는다.

## 동작

- 현재 장면을 유지하면서 피치·요·롤 카메라 계수만 출력코어에 전달한다.
- PC에서 기존 Python 기준 모델로 경로를 생성한다. 실행 중 CPU는 180개 계수를 전달하며 픽셀/타일/카메라 삼각함수를 다시 계산하지 않는다.
- 120개 자세, 목표 간격 50ms, 반복 주기 약 6초. 실제 갱신률은 실보드 측정값을 별도로 기록한다.
- 요청을 쌓지 않는다. 늦었으면 현재 시각에 해당하는 자세로 건너뛴다. 장치의 프레임 경계 완료 응답 이후 성공으로 기록한다.
- 데몬의 기존 장치 소유권과 드라이버 ioctl을 사용한다. 장치 파일을 다른 프로세스가 동시에 조작하지 않는다.
- 미리보기 동안 창 내용 갱신과 포인터/클릭 처리를 멈춘다. 창·입력을 변경하는 요청은 명시적으로 거부한다. 일반 창 조작과 동시에 동작하는 완성된 애니메이션 시스템은 아니다.
- 명시적 정지, 지정 시간 만료, 조작 클라이언트 연결 종료 시 원래 카메라와 WM 시점으로 복원한다. 장치 오류 시 성공한 것으로 상태를 갱신하지 않는다.
- 상태 조회는 별도로 가능하며 작은 진행 상태만 최대 초당 2회 게시한다. 전체 창 상태를 매 프레임 복사하지 않는다.

## 실행

새 실행 파일로 데몬을 시작한 뒤 사용한다. 기존 v7 실행 파일에는 아래 명령이 없다.

```sh
/tmp/boayo-view-v8 view-play /tmp/view-path.bin 60
/tmp/boayo-view-v8 view-status
/tmp/boayo-view-v8 view-stop
```

재생 시간은 1~300초. 전경 재생 명령은 Ctrl+C로 정지할 수 있다. 임시 배포 파일은 RAM의 `/tmp`에 위치하며 전원을 끄면 사라진다. 기존 SD 실행 파일은 덮어쓰지 않는다.

## 검증 범위

`tests/test_view.cpp`: 모든 경로 계수의 Python/C++ 일치, 중복 틱 억제, 지연 건너뛰기, 원상복구, 시간 만료, 장치 실패 상태.

`tests/test_view_service.py`: 실제 서비스 IPC, 조회, 중복 시작/창 변경 거부, 파일 길이·체크섬 오류, 정지 및 연결 종료 복구.

기존 motion-v7의 혼합 자세 및 25단계 동작 검증도 새 호스트 실행 파일로 재실행한다. Mock 검증은 실보드 동작 증거와 구분한다.

장면 계층의 `backend.*`, `wm.cpp`, `geometry.*` 등은 motion-v7과 동일하며 기존 사전 계산 장면 버전 `c830e2bae43593f8c188620447b4ce808ce4894a826a073b44f12b949ad54b7e`를 유지한다.

## 배포 도구

UART는 HVC 콘솔이므로 이진 제어 문자를 그대로 보내면 안 된다. `tools/uart_receive.c`는 256바이트씩 16진수로 받고 각 블록의 누적 FNV와 최종 길이를 확인한다. 원본 ELF를 이용한 델타는 전송량을 줄이는 배포 전용 도구다. 원본·재구성 결과의 해시를 확인하며 원본 파일은 수정하지 않는다. 최종 SHA-256은 호스트의 검증된 산출물과 연결해 보관한다.

`tools/make_delta.py`의 bsdiff4/liblz4 의존성은 PC에만 필요하다. FPGA Linux에는 설치하지 않는다.

## 2026-11-14 실보드 결과

20초 동안 201회 카메라 적용(평균 약 10.05회/초), 오류 없음. 처리 시점이 지난 198개 샘플은 누적하지 않고 건너뛰었다. 최대 장치 적용 시간은 약 98.85ms. 종료 후 yaw/pitch/roll 8°/4°/8° 복귀 확인. HDMI에서 서로 다른 8개 시점 캡처 확인. 목표 20회/초는 미달이며 기존 글자·테두리 깨짐은 남아 있다. 이후 300초 연속 재생을 시작했다.
