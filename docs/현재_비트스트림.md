# 현재 HAEBANCHEON 비트스트림과 공개 소스

2026-11-17 기준 실보드에 사용한 RTL은 **`variants/l1-16k-dma3-lru-ram/`**이다. 저장소 루트는 2026-11-08 기준본이며 `variants/sd4-dma/`, `variants/l1-16k-dma3/`, `variants/l1-32k-dma3/`는 이전 구성/비교본이다. 서로 다른 폴더의 RTL을 섞지 않는다.

## 기준과 확인 범위

| 항목 | 현재 구성 |
|---|---|
| 보드 / FPGA | PZ-A7200T-KFB / xc7a200tfbg484-2 |
| top | `gen3_kfb_bosio` |
| 비트스트림 | `HAEBANCHEON-KFB-L1-16K-DMA3-v1.bit` |
| SHA-256 | `9bb855886be0ac55d983f9a72ab0e6c23317b7f4fe27e13430cb2de17d7d4e07` |
| CPU | ORYUKDO RV32IMA, 3 Decode / 5 Issue, Sv32, I/D 각각 TLB 8-entry |
| 실행기 | Branch/CSR 1 + ALU 2 + MULDIV 1 + LSU 1 |
| L1 | I/D 각각 16KiB·2Way·32B line, D write-through |
| 메모리 / 주변장치 | MIG DDR3 1GiB, SD4, DMA 3개, PLIC, UART 2개, SPI, I2C |
| BOSIO | 투영코어 2개, 출력코어, 센서 허브, HDMI2 연결 |
| CPU / fabric / HDMI pixel | 50 / 100 / 74.25MHz |
| 배선 후 LUT / FF / BRAM / DSP | 119,141 / 76,182 / 110 tiles / 62 |
| 배선 후 Setup / Hold | WNS +0.093ns / WHS +0.011ns, TNS/THS 0 |

위 구현 수치는 보존한 실제 배선 결과다. 이번 게시를 위해 RTL을 변경하거나 합성·배선을 재실행하지 않았다. 이후 [v14 실보드 결과](../updates/boayo-tilebatch-v14/BOARD_RESULT_KO.md)는 Linux 셸·앱·HDMI 동작을 확인했다. 초기 `provenance/release_manifest.json`의 `physical_board_tested=false`는 제작 당시 기록으로 보존하며 후속 실보드 결과와 함께 읽는다. v14는 기능 동작을 관측했지만 앱 갱신 성능은 비교본보다 느려졌다.

## 포함 및 제외

- 포함: CPU/스케줄러/실행기/MMU/L1, AXI fabric·CDC, SD/DMA/PLIC, BOSIO 투영·출력·센서 RTL, 직접 작성한 MIG/HDMI 연결 RTL, 핀·클럭 XDC, MIG 설정 `mig_a.prj`, 생성·합성·구현 Tcl, 테스트 및 보존 리포트.
- 제외: AMD MIG 생성 RTL·XCI·DCP, Vivado XPM 라이브러리, 모든 구성의 외부 HDMI IP 원본, 비트스트림·SD 이미지·배선 DCP.
- HDMI는 고정 upstream commit과 파일별 SHA-256 목록을 게시한다. 빌드 전에 공식 소스를 따로 받는다. 직접 작성한 `kfb_hdmi.sv`와 보드 제약은 포함한다.
- MIG는 설치된 Vivado 2022.2의 MIG 4.2에서 설정 파일로 생성한다. XPM도 같은 Vivado 설치본을 사용한다.
- 기존 루트/SD4의 HDMI 원본도 최신 Git 트리에서 제거했다. 과거 커밋 이력은 유지한다. 모든 구성의 [공통 외부 준비 방법](외부_HDMI.md)을 따른다.

## 구조·주소·인터럽트·요청 형식

[전체 검토 자료](HAEBANCHEON_SOC_REVIEW_PROMPT_KO.txt)에 전체 연결도, 주소 맵, PLIC source, 투영 18word descriptor, 출력 scene/camera, DMA register job, 현재 Linux UAPI와 실제 사용 DT를 수록했다. [근거 소스 해시](HAEBANCHEON_SOC_REVIEW_SOURCES.json)도 함께 제공한다.

투영0 `0x20000000`, 투영1 `0x20010000`, 출력 `0x20020000`, SD `0x10008000`, DMA0/1/2 `0x10009000/0x1000a000/0x1000b000`. PLIC source 1/2/3/4는 각각 SD/DMA0/DMA1/DMA2이며 BOSIO 완료는 polling이다. DDR `0x80000000..0xbfffffff` 중 arena `0xbd000000..0xbdffffff`, 영상 `0xbf800000..0xbfffffff`는 예약 영역이다.

v14 이미지 빌드는 최종 HW 폴더의 `software/bosio/gen3-bosio.dts`를 사용한다. v14 SW 폴더에 남은 구형 DMA1개 DT를 실제 사용 DT로 오해하지 않는다. Linux API 기준은 `updates/boayo-tilebatch-v14/software/bosio/include/bosio_uapi.h`다.

## 새 checkout에서 입력 준비·확인

저장소 루트에서 Python 3으로 실행한다.

```sh
python scripts/verify_current_rtl.py --require-tracked
python scripts/prepare_current_hdmi.py
python scripts/prepare_current_hdmi.py --check-only
```

첫 명령은 원래 구현 소스 해시, 보존 RTL 로그 44개, LRU 로그 3개 및 Git 입력 누락을 확인한다. 28개 `.sh`의 줄바꿈 차이와 별도 해시로 기록한 게시용 도구 변경을 구분하며 RTL 바이트 불일치는 허용하지 않는다. 기능 테스트를 새로 실행하는 명령이 아니다.

HDMI 준비 도구는 upstream `0362ce72d39eebc400fdabacff706ee7fa8ad564`의 11개 파일을 확인한다. 해시가 다른 기존 파일은 덮어쓰지 않고 중단한다. 받은 `src/`와 `component.xml`은 Git ignore 대상이다. 모든 구성의 `verify_vendor.py`도 공식 IP만 검사하도록 갱신했다. 미사용 보드 예제 HDL은 빌드에 필요하지 않다.

## Vivado 재구현

Windows PowerShell 예시다. 설치 경로와 비어 있는 출력 경로를 맞춘다. 각 명령의 종료 코드/PASS를 확인한 뒤 다음 단계를 실행한다.

```powershell
$vivado = 'D:/Xilinx2202/Vivado/2022.2/bin/vivado.bat'
$variant = (Resolve-Path 'variants/l1-16k-dma3-lru-ram').Path
$output = 'D:/build/haebancheon-current'
& $vivado -mode batch -source "$variant/soc/board/build_mig.tcl" -tclargs "$output/mig"
$mig = "$output/mig/kfb_bosio_mig.srcs/sources_1/ip/mig_7series_0/mig_7series_0.xci"
& $vivado -mode batch -source "$variant/soc/board/build_area_medium_synth.tcl" -tclargs "$output/synth" $mig
& $vivado -mode batch -source "$variant/soc/board/place_only.tcl" -tclargs "$output/synth/optimized.dcp" "$output/place"
& $vivado -mode batch -source "$variant/soc/board/prepare_output_fanout.tcl" -tclargs "$output/place/placed_optimized.dcp" "$output/fanout"
& $vivado -mode batch -source "$variant/soc/board/route_from_placed.tcl" -tclargs "$output/fanout/fanout_optimized.dcp" "$output/route"
```

마지막 Tcl은 route·timing·DRC/CDC/보드 검사를 통과한 경우에만 비트스트림을 쓴다. 선택된 fanout net/보호 DSP가 새 배치에 없으면 의도적으로 중단한다. 이름 검사나 타이밍 gate를 제거하지 않는다.

기존 성공 구현은 보존된 배치 DCP에서 이어진 결과다. 새 배치의 자원·타이밍·비트스트림 바이트 동일성을 보장하지 않는다. 특히 여유가 작으므로 새 배선 결과로 판단해야 한다. 원래 연결 순서는 `provenance/implementation_chain.json`, 입력 해시는 `implementation_source_manifest.json`, 결과는 `reports/`다. 대형 DCP는 Git에 포함하지 않았다.

## 기능시험과 소프트웨어

WSL/Linux, Verilator, RISC-V toolchain, 설치된 Vivado의 XPM이 필요하다. 기존 로그를 보존할 별도 checkout에서 실행한다.

```sh
cd variants/l1-16k-dma3-lru-ram
export XPM_ROOT=/path/to/Vivado/2022.2/data/ip/xpm
bash software/storage/test_all_l1.sh
bash software/storage/test_lru_equivalence.sh
```

이번 게시에서는 장시간 회귀, RTL Linux 콜드 부팅, 보드 전원/업로드를 다시 실행하지 않았다. SD 최신 빌드에는 이전 userspace/커널 작업 트리 의존성이 남아 있다. RTL 공개만으로 완전한 새 SD 빌드 환경까지 자동 준비된다는 뜻은 아니다. `updates/`는 현재 SW와 비교 기록이며 각 버전의 검증 범위를 따른다. 종료 절차와 정밀 타일 계측의 후속 요구는 아직 구현 완료가 아니다.
